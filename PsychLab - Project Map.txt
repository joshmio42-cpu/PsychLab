WHAT PSYCHLAB DOES

PsychLab is an experimental psychological interviewing practice application.
A learner chooses a fictional person, prepares a history, interviews that person,
records evidence and provisional reasoning, and receives an evidence-linked debrief.
The central rule is that history is generated locally and frozen before the
interview. Model-generated speech cannot create new case facts or change history.
Personality, biography, goals, relationships and clinical presentation are separate.

The project began with one scripted adult case and has grown into a live AI app.
Old foundation documents describe the earlier milestone and are not reliable
standalone accounts of current functionality.

APPLICATION FLOW AND CODE OWNERSHIP

1. live/public/index.html, app.mjs and style.css provide the interface.
   Setup selects patient, 1–90 recent days, seed and difficulty, followed by a
   chosen condition, Random mystery case, or No disorder.
2. live/server.mjs provides HTTP endpoints; controller.mjs owns sessions,
   preparation, turn submission, notes, assessment, completion and reviewer access.
3. patients.mjs and individuality.mjs supply life-stage scenarios and stable
   authored personal facts. disorders.mjs and live/data/ provide condition
   premises, earlier course, current experiences and functional impacts.
4. engine.mjs generates a seeded history and freezes the result with a SHA-256
   fingerprint. Simulation modules represent physiology, memory, appraisal,
   affect, social action, world consequences and identity learning. These are
   local computations, not separate paid AI agents. The history window does not
   age a person from birth. Random case selection is separate from the diary seed.
5. model.mjs calls Featherless for CORTEX fact routing, LANGUAGE patient speech,
   and AUDITOR support/relevance review. conversation.mjs, question-resolution.mjs,
   factual-support.mjs, prompt-context.mjs, interview-style.mjs and agent-context.mjs
   handle memory retrieval, callbacks, factual checks, prompt limits, disclosure
   and a read-only personality projection. Source IDs refer to frozen evidence;
   earlier generated replies do not become new evidence.
6. interview-guide.mjs and interview-feedback.mjs support evidence-linked notes,
   follow-up questions, provisional reasoning and local debrief feedback. This
   work adds no model calls. The five competence ratings remain NR.
7. The server holds active sessions in memory. Browser History stores disclosed
   transcripts and saved learner work in localStorage, separately from hidden
   case state and reviewer traces. Full reviewer access requires completion.

answer-plan.mjs and evidence-render.mjs implement the optional staged path:
partition the question, validate quoted sources, preserve known/unknown distinctions,
then write from permitted evidence. Conservative exact-excerpt repair can replace
an insufficient draft. It can reduce naturalness and is not a general factual proof.

OPERATING DETAILS

Requires Node 22+ according to the live README; this examination used Node 24.15.0.
The app uses Node built-ins and plain browser modules, with no npm build workflow.
From the live folder, node server.mjs defaults to port 8770.
Open PsychLab.cmd / Start-PsychLab.ps1 defaults to 8771 and uses saved Windows
DPAPI credentials outside the workspace. Setup PsychLab.cmd configures those.

Default budgets: 60 attempted calls per interview, 300 per server process;
12,000 input bytes per call; output caps 640/320/192 for router/writer/auditor.
Ordinary supported turns use up to three calls. Some local/social/boundary paths
use fewer. No automatic paid retries. Token-based costs are estimates, not invoices.
Sessions expire after two hours idle; maximum 64 sessions and 80 turns per session.
Browser History keeps up to 50 conversations and is specific to browser/origin.

Domain Connection Status.txt records a Cloudflare tunnel to psychlab.example.com with
email-code Access and origin-side signed JWT checks. This is historical setup
evidence. During this examination neither local status endpoint on 8770 nor 8771
was reachable. Public hosting, authenticated access and current credentials were
not reverified, and no real provider calls were made.
